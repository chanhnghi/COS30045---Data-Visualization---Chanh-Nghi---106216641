ABOUT / THE PROJECT

Useful stories start with honest data.

Still On is a COS30045 Data Visualisation project built around an Australian TV register snapshot. It asks how daily viewing hours, standby modes, and screen size change projected yearly electricity use.

W⚡

01 / PURPOSE

Built to ask better questions.

Choose up to four real model rows to compare viewing-hour scenarios. Then inspect how viewing and standby power contribute to the total, and how a two-hour reduction varies across screen-size groups.

The older register scatterplot remains below the new story. It shows the source's labelled annual kWh, which is a different measure from our viewing-hour projections.

02 / THE METHOD

What went into this view.

01

Source

tv_2026_10_03.csv, a television registration snapshot dated 3 October 2026. Its rows describe registered models, not purchases or households.

02

Selection

We keep approved models marked “Available” and sold in Australia. Of 5,340 source rows, 4,844 meet those conditions and 3,990 have complete numeric viewing and standby power fields. Screen size is converted from centimetres to inches.

03

Projection

For h viewing hours per day: yearly kWh = 0.365 × [h × viewing W + active-standby hours × active W + (24 − h − active-standby hours) × passive W]. We evaluate h = 2, 4, 6, 8, and 10.

04

Limits

These scenarios hold active-standby hours fixed and assume the same pattern every day. They are simulations from model specifications, not measurements of households or bill forecasts. “Available” is not a live stock check.

03 / RESPONSIBLE USE

Make the workings visible.

The KNIME workflow prepares and visualises the three angles. The website uses the same selection and projection rules to make the model and cohort filters respond immediately in the browser. A registration number may cover several model rows, so each chart count refers to model rows. The standby bars are means of different sets of models; differences between those groups cannot be attributed to standby alone.

The website uses three HTML pages, one shared CSS file, and vanilla JavaScript. OpenAI Codex assisted with planning, visual design, implementation, and debugging. The README records the calculations and limitations for review.
